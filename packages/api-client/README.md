# @agent-repo-template/api-client

The typed HTTP client for backend, generated from `backend/api/openapi.yaml`.

- `src/schema.d.ts` is generated by openapi-typescript and committed. Never edit it by hand; after
  changing backend's spec, run `npm run generate -w packages/api-client` and commit both together.
- Private and unversioned (`"private": true`, version `0.0.0`); Changesets leaves it alone.
- Consumed as TypeScript source (`exports` → `./src/index.ts`): no build, no `dist/`, no tests.

## Exports

- `createApiClient(baseUrl)` — openapi-fetch's `createClient<paths>`, with no middleware.
- `paths` — the generated paths with every response retyped as backend's envelope: a JSON body
  becomes `Envelope<body>`, a content-less one `Envelope<null>`, `204` and `304` stay bodiless, and
  each operation gains a `default` failure envelope (non-null `code`, `null` payload).
- `Envelope<T>`, `ErrorCode` (from the spec's `ErrorCode` schema), and the generated `components`
  and `operations`.

Retyping is type-level only: `{ data, error, response }` reach the caller exactly as they arrived, so
the caller reads `data.payload` and `error.code` itself.

## Consuming it

Declare it in the consumer's `package.json` `dependencies` as `"@agent-repo-template/api-client": "*"`.
Next.js consumers list it in `transpilePackages`, since it ships TypeScript.

## Lint

`npm run lint -w packages/api-client` runs `tsc --noEmit`, then regenerates into a temporary folder
under `.scratch/` and fails on any difference from `src/schema.d.ts`. `turbo.json` names backend's
spec as a lint input, so a spec edited without regenerating fails `make check` even on a warm cache.
