# ai conventions

The Python service for AI capabilities: a modular monolith serving gRPC, internal only. Decisions with
their reasons are in [`docs/adr/`](./docs/adr/); system-wide ones in the root
[`docs/adr/`](../docs/adr/).

## Libraries (hard rules)

| Concern | Use | Never |
| --- | --- | --- |
| RPC | grpcio's thread-pool server ([ADR 0001](./docs/adr/0001-thread-pool-grpc-server.md)) | `grpc.aio`, an HTTP framework (FastAPI, Flask) |
| Protobuf | the buf-generated stubs in `gen/`, protobuf bounded `>=7.36.2,<8` | hand-written messages, `types-protobuf` |
| Health | `grpcio-health-checking`'s synchronous `HealthServicer`, on grpcio's version, typed by `types-grpcio-health-checking` | a custom health RPC, `health.aio`, `enter_graceful_shutdown` |
| Config | pydantic-settings, from the mapping `main` receives | `os.environ` read directly, `.env` files, secrets directories |
| Logging | structlog, configured once in `platform/logging.py` | `print`, hand-written formatters |
| Packaging | uv, hatchling | pip, poetry, a hand-edited `uv.lock` |
| Lint | Ruff, mypy `strict` with `types-grpcio` | `# type: ignore`, `ignore_errors`, loosened flags on `aisvc` |
| Boundaries | import-linter, in the dev group, run with `--no-cache` | `exclude_type_checking_imports`, a second `layers` contract |
| Tests | pytest, pytest-socket | pytest-asyncio, unittest |
| Hot reload | watchfiles, in the dev group and the `dev` Docker target only | Compose Watch |

The distribution and the import are both `aisvc`: the generated code owns the top-level `ai`. The npm
workspace stays `"name": "ai"`, because turbo and Changesets key on it.

## Layout

```
gen/                # generated by buf from ../proto, never hand-edited
scripts/lint.sh     # lock check, Ruff, Ruff format, mypy, import-linter
scripts/lint-fix.sh # Ruff autofix, then Ruff format
src/aisvc/
  __main__.py       # composition root: argparse subcommands, `serve` and `healthcheck`
  platform/         # infrastructure, never AI logic
    config.py       # Settings, validated from the environment mapping
    logging.py      # the one structlog setup
    buildinfo.py    # version and commit from the generated _buildinfo.py, else dev
  rpc/              # server assembly, servicers, the graceful stop
    server.py       # assemble() and stop(), module registration, and the 16 / 64 / 20 s constants
    info.py         # ai.v1.InfoService
    health.py       # grpc.health.v1: the registered names, the drain and the probe
    interceptors.py # the request-ID interceptor and the error guard
  modules/          # one AI capability each; empty for now
    <m>/
      __init__.py   # public interface: register(server), plus what other modules may call
      model.py      # types that are shape only
      _internal/    # the servicer, the service and the provider adapters; private
tests/              # mirrors src/aisvc/
```

- Imports run one way only: `__main__` → `rpc` → `modules` → `platform`. `platform` imports nothing
  above it. import-linter enforces this as one `layers` contract in `pyproject.toml`, counting
  `TYPE_CHECKING` imports too.
- Info is a platform concern and lives in `rpc`, not in a module.

## Modules

Each module is one AI capability serving one `ai.v1.<Module>Service`, with the shape in
[Layout](#layout).

- **Imports.** A module imports `platform` and other modules' `__init__` only. It never imports `rpc`,
  not even under `TYPE_CHECKING`, and never another module's `model.py` or `_internal/` except through
  what that `__init__` re-exports.
- **Privacy.** Each module adds its own `protected` contract to `pyproject.toml`, so only its own
  package reaches `_internal/`:

  ```toml
  [[tool.importlinter.contracts]]
  name = "<m> internals are private"
  type = "protected"
  protected_modules = ["aisvc.modules.<m>._internal"]
  allowed_importers = ["aisvc.modules.<m>"]
  ```

- **Registration.** `__init__.py` exposes `register(server)`. `server` offers two things: `grpc_server`,
  where the module adds its servicer with the generated `add_<Module>ServiceServicer_to_server`, and
  `add_health(name)`, called with the proto service's full name. That entry is `SERVING` once the
  server starts and turns `NOT_SERVING` with the rest on stop. A module never sets a health status,
  never touches `""`, and never drains or stops.
- **The `server` type.** Since a module may not import `rpc`, it annotates `server` with a
  `typing.Protocol` it declares itself, holding only those two members. `rpc.server.Registration`
  satisfies it structurally, and `assemble` accepts modules through its own `Module` Protocol, so mypy
  checks each module against `rpc`'s object where it is passed in.
- **Wiring.** By hand: `serve` in `__main__.py` passes the module objects to `assemble`, which
  registers them before the server starts. No discovery, entry points or DI container.
- **Providers.** A module reaches an external provider through a narrow `typing.Protocol` that the
  calling code declares. Tests fake that Protocol; the adapter in `_internal/` is tested against
  recorded responses.

## Errors

`rpc/interceptors.py` holds the error guard, the second interceptor on the server that `assemble`
builds, after the request-ID interceptor (see [Logging](#logging)), so `serve` and the tests both have
it.

- It covers unary RPCs. Any exception a handler raises is logged as one error event with its
  traceback, the RPC's method name and the call's bound `request_id`, never the request, other
  metadata or the peer. The caller gets
  `INTERNAL` with a fixed generic message: exception text can carry personal data and never reaches
  backend.
- Servicers raise; they never call `context.abort` or set a status code. The guard cannot tell a
  deliberate abort from a failure, so an abort also comes out as `INTERNAL`.
- Streaming handlers pass through untouched, because rewrapping them drops grpc's non-blocking flag
  that health's `Watch` needs. A module that adds a streaming RPC extends both interceptors to it.
- There are no error kinds yet; the first module that needs a status other than `INTERNAL` adds them.

## CPU-bound work

The server is a thread pool, so a blocking call costs one worker rather than every RPC
([ADR 0001](./docs/adr/0001-thread-pool-grpc-server.md)). CPU-bound work still has one rule:

- Libraries that release the GIL (numpy, onnxruntime, torch) run on the handler thread.
- Pure-Python CPU-bound work goes to a process pool; on a handler thread it holds the GIL and slows
  every other RPC.
- No free-threaded Python build: grpcio publishes no free-threaded wheels.

## Configuration

pydantic-settings validates one `Settings` from the environment mapping `main` receives. It reads no
`.env` file and no secrets directory. A bad environment is reported all at once, naming every bad
variable by its environment name, as one JSON log line; `serve` then exits 1 before anything is bound.

| Variable | Notes |
| --- | --- |
| `APP_ENV` | Required: `dev`, `staging` or `production` |
| `PORT` | Integer 1–65535, default `50051` |

Exit code 2 stays reserved for argparse usage errors, because Docker reserves exit code 2 for health
checks.

## Logging

structlog from `platform/logging.py`: console output in dev, JSON otherwise, written to the stdout
current at each `main` call. A configuration failure is always JSON, since `APP_ENV` may be what
failed. Never log secrets or personal data.

`configure` puts structlog's `merge_contextvars` first in the chain, so both renderers print whatever
is bound through `structlog.contextvars`.

- **The request ID.** Every line logged during a unary call carries that call's ID under
  `request_id`, the key backend uses. It is the call's first `x-request-id` metadata value, taken
  verbatim; when none arrives or it is empty, a new one is assigned in the shape backend's
  `crypto/rand.Text()` produces: 26 characters of the
  [RFC 4648 base32 alphabet](https://www.rfc-editor.org/rfc/rfc4648#section-6), drawn with `secrets`.
  Nothing is sent back to the caller.
- **The interceptor order.** `assemble` passes `[RequestId(), ErrorGuard()]`. grpc runs the first
  outermost, so the guard's `rpc failed` line (see [Errors](#errors)) is written while the ID is bound.
- **Bound inside the call.** The interceptor reads, assigns and binds the ID inside the wrapped
  behaviour, with `structlog.contextvars.bound_contextvars`, never in `intercept_service`. That ties
  the ID to the call's lifetime, on the thread that writes its lines, and unbinding when the call
  returns, aborts or raises keeps it off whatever runs next there. Neither depends on grpcio giving
  each call its own `contextvars` context, which lives in its private `grpc._server`. Never bind
  through a bound logger, a raw `ContextVar`, `threading.local` or a module global.
- Streaming handlers pass through untouched, as in the guard, so a streaming call's lines carry no
  `request_id`.

## Runtime

- `GetInfo` answers `service: "ai"` and the build's version, never the commit.
- The startup log line carries the service, version, commit and environment; it is the only place the
  commit appears.
- `rpc/server.py` builds `grpc.server(ThreadPoolExecutor(max_workers=16), maximum_concurrent_rpcs=64)`;
  beyond 64, gRPC answers `RESOURCE_EXHAUSTED`. The 16, the 64 and the 20 s grace are module constants,
  never configuration. `serve` and the test fixture both use this one function.
- Health is `grpc.health.v1`. `""` means readiness, and in the skeleton it depends on nothing: it is
  `SERVING` once the server starts. Each registered service, `ai.v1.InfoService` today, has its own
  name beside it. There is no liveness status; liveness is the port accepting connections.
- On `SIGTERM` or `SIGINT`: the handler only calls `rpc.server.stop`, which first sets every registered
  health name `NOT_SERVING` with `set`, then refuses new RPCs and drains in-flight ones for up to 20 s;
  `main` then returns 0. Docker stops with `SIGTERM` and watchfiles reloads with `SIGINT`, so both drain
  alike. Compose's `stop_grace_period` is 30 s.
- A draining container's port closes at once, so a new probe fails to connect rather than reading
  `NOT_SERVING`. That is intended: both read as not ready, and only already-connected clients (an open
  `Watch`) can see `NOT_SERVING`.
- `python -m aisvc healthcheck` calls `Check("")` on `localhost:PORT` with a 2 s deadline and exits 0
  only on `SERVING`, 1 on anything else, never 2. It binds nothing and is silent on success. Compose
  and the production image's `HEALTHCHECK` both run it.
- In dev, `docker compose stop` gives the server only 5 s, not 20: watchfiles applies
  `--sigint-timeout` to reloads only, and stops its child on exit with its default 5 s.
- Nothing is held in process memory between RPCs: two copies run side by side during a deploy
  ([ADR 0005](../docs/adr/0005-deployment-topology.md)).

## Build

`Dockerfile`, built from `ai/`, every stage `FROM python:3.14-slim` through the public ECR mirror
(`public.ecr.aws/docker/library/`), which avoids Docker Hub's pull limits:

- Every image reference carries its tag and its multi-arch index digest, so a rebuild never changes
  base silently. A bump changes both together, the digest read from
  `docker buildx imagetools inspect <image:tag>`.
- Build stage: uv copied from `ghcr.io/astral-sh/uv`, pinned to the version `devbox.lock` resolves, so
  the host and the image read `uv.lock` alike; the pin moves whenever `devbox.lock`'s uv does. It
  writes `src/aisvc/platform/_buildinfo.py` from the `VERSION` and `GIT_SHA` args (both default to
  `dev`), then `uv sync --locked --no-dev --no-editable` into `/opt/venv`. uv never downloads a
  Python.
- `_buildinfo.py` is gitignored and listed as a hatch wheel `artifacts` entry; hatchling drops
  VCS-ignored files from wheels otherwise, and production would report `dev`.
- `dev` target: the dev group with editable installs, and watchfiles restarting `python -m aisvc
  serve` over the bind-mounted `src`. The mount hides the image's `_buildinfo.py`, so dev reports
  `dev`.
- Production target: the base image plus `/opt/venv` only, with no uv and no source tree, run as a
  non-root user.

## Tests and lint

- Tests live in `tests/`, mirroring `src/aisvc/`, under plain pytest. Test file basenames stay unique
  across the tree.
- pytest runs with `--disable-socket --allow-hosts=127.0.0.1,::1`: no test reaches beyond loopback.
- Tests assert what a caller sees: status codes, response fields, exit codes and messages, never
  wiring or servicer internals. The `channel` fixture in `tests/conftest.py` builds the server with
  `assemble`, binds loopback port 0 and talks through a real channel and the generated stubs.
- A test that stops a server owns that server. No test signals the pytest process, and every wait is
  bounded.
- Lint (`scripts/lint.sh`): `uv lock --check`, `ruff check`, `ruff format --check`, `mypy`
  (strict, over `src` and `tests`), then `lint-imports --no-cache`. The flag matters: import-linter's
  default cache directory is not gitignored. Every tool runs through `uv run --locked` from the dev group, and
  neither lint nor test rewrites `uv.lock`, because turbo runs them at the same time. Ruff excludes
  `gen/`; the one mypy exception is `untyped_calls_exclude = ["ai.v1"]`, as buf's stubs cover the
  `_pb2` modules only.
- Fix (`scripts/lint-fix.sh`, `lint:fix`): `ruff check --fix --exit-zero`, then `ruff format`, both
  through `uv run --locked`. The pre-commit hook runs it before its gate.
